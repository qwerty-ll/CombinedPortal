# 48. ПРОВЕРКА FAILURE COMBINATIONS

```text

Deploy + old event

```

# 49. ПОИСК НЕСОВМЕСТИМЫХ ПРЕДПОЛОЖЕНИЙ

```text id="k64dzr"

Это один из главных источников системных багов.

PAY → REFUND
ADD → REMOVE
ENABLE → DISABLE

```

Проверь race между forward и reverse operations.

START

# 62. АБСОЛЮТНЫЕ ПРАВИЛА

### Правило 1

Никогда не говори:

> "Всё хорошо."

Пока не проверены failure scenarios.

### Правило 2

Не считай наличие теста доказательством корректности.

### Правило 3

Не считай наличие transaction доказательством consistency.

### Правило 4

Не считай наличие Redis lock доказательством отсутствия race condition.

### Правило 5

Не считай retry безопасным без idempotency.

### Правило 6

Не считай event-driven architecture надежной без обработки duplicate/lost/out-of-order events.

### Правило 7

Не считай auth middleware достаточным доказательством authorization.

### Правило 8

Не считай cache частью source of truth, пока это явно не доказано.

### Правило 9

Не считай network call успешным только потому, что код ожидает response.

### Правило 10

Не останавливайся после первого найденного бага.

# 63. ФИНАЛЬНАЯ КОМАНДА

**ПРОВЕРЬ ПРОЕКТ ПОЛНОСТЬЮ С НУЛЯ.**

Не ориентируйся на предыдущие аудиты.

Не пропускай код, который "выглядит простым".

Не анализируй только happy path.

Для каждой критической части обязательно рассматривай:

```text
normal
invalid
concurrent
duplicate
retry
timeout
partial failure
out-of-order
stale state
restart
recovery
deployment
scale
security abuse
data corruption
```

Главная цель:

> **найти не просто баги, а любые сценарии, при которых система перестает гарантировать правильность, безопасность, целостность, консистентность, доступность или восстановимость.**

Работай до тех пор, пока не проверишь систему одновременно как:

**разработчик + злоумышленник + пользователь + оператор + база данных + очередь + сеть + случайный failure generator.**

Не делай поверхностный review.

**Это forensic-аудит всего проекта с нуля.**
